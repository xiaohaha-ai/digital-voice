# React + TypeScript + Vite

## Model Providers

The application defaults to a no-cost, no-weight-download configuration. Copy `.env.example` to `.env.local` only when configuring providers. No paid API is enabled by default.

| Capability | Default | Remote model |
| --- | --- | --- |
| PPT structure | local parser | python-pptx + LibreOffice can replace it later |
| Script generation | mock | configurable LLM provider |
| Voice synthesis | mock | CosyVoice 3 |
| Avatar lip sync | mock | MuseTalk 1.5 |
| Image background removal | mock | BiRefNet |
| Video background removal | mock | Robust Video Matting |

Set `VOICE_PROVIDER=remote`, `AVATAR_PROVIDER=remote`, `IMAGE_BACKGROUND_PROVIDER=remote`, or `VIDEO_BACKGROUND_PROVIDER=remote` together with `GPU_WORKER_BASE_URL` to enable a private NVIDIA GPU Worker. The worker receives authenticated multipart requests at:

- `POST /internal/voice/synthesize`
- `POST /internal/avatar/generate`
- `POST /internal/background/image`
- `POST /internal/background/video`
- `GET /internal/health`
- `GET /internal/jobs/{job_id}`

The worker may return generated bytes, a JSON Base64 result, a download URL, or a queued `job_id`; completed artifacts are copied into this service's `/uploads` directory. Check configured modes with `GET /api/providers/status`.

## Digital Person Video

Creating a digital person video uses this sequence:

1. Upload a portrait with `POST /api/uploads/image` and audio with `POST /api/uploads/avatar-audio`.
2. Submit the authorized pair to `POST /api/digital-people/avatar` with `name`, `portraitPath`, `audioPath`, and `consent: true`.
3. If the response is queued, poll `GET /api/people/{id}/video-status` until `videoStatus` becomes `ready` and `videoPath` points to the generated MP4.

Real lip-sync video requires `AVATAR_PROVIDER=remote` plus a reachable `GPU_WORKER_BASE_URL` running MuseTalk 1.5. The default Mock mode deliberately rejects digital-person video creation rather than returning a non-synced placeholder video.

### Volcano Engine OmniHuman 1.5

OmniHuman 1.5 can replace the private GPU Worker. Set `AVATAR_PROVIDER=volcengine`, then configure `VOLCENGINE_ACCESS_KEY_ID`, `VOLCENGINE_SECRET_ACCESS_KEY`, and `VOLCENGINE_PUBLIC_UPLOAD_BASE_URL` in `.env.local`. The public upload base must map to this application's `/uploads` directory, for example `https://your-domain.example/uploads`.

The server submits `CVSubmitTask` to the Volcano Engine Visual API and polls with `CVGetResult`. Uploaded portrait and audio files must be reachable by the API. Generated `video_url` values are downloaded immediately because the provider URL expires after one hour.

### Deploying to a Public ECS

The included Nginx configuration serves the Vite build, proxies `/api` to the Node service, and exposes `/uploads` for OmniHuman input. On the ECS server:

```bash
sudo mkdir -p /opt/digital-person
# Upload the project source to /opt/digital-person, then run:
cd /opt/digital-person
npm ci
npm run build
sudo cp deploy/nginx/digital-person.conf /etc/nginx/sites-available/digital-person
sudo ln -s /etc/nginx/sites-available/digital-person /etc/nginx/sites-enabled/digital-person
sudo rm /etc/nginx/sites-enabled/default
sudo cp deploy/systemd/digital-person.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now digital-person
sudo nginx -t && sudo systemctl reload nginx
```

Create `/opt/digital-person/.env.local` with `AVATAR_PROVIDER=volcengine`, the Volcano Engine credentials, and `VOLCENGINE_PUBLIC_UPLOAD_BASE_URL=http://your-public-ip/uploads` before starting the service. Use an HTTPS domain before accepting real user portraits or voice recordings in production.

For slide summaries and scripts, `POST /api/ppts/{id}/scripts/generate` uses deterministic mock text by default. Set `LLM_PROVIDER=remote`, `LLM_BASE_URL`, and `LLM_MODEL` only when intentionally enabling an OpenAI-compatible local or cloud LLM endpoint.

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend enabling type-aware lint rules by installing `oxlint-tsgolint` and editing `.oxlintrc.json`:

```json
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "plugins": ["react", "typescript", "oxc"],
  "options": {
    "typeAware": true
  },
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

See the [Oxlint rules documentation](https://oxc.rs/docs/guide/usage/linter/rules) for the full list of rules and categories.
